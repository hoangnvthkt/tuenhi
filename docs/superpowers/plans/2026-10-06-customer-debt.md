# Customer debt implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Split payment, customer credit, collection and reasoned balance adjustments.
**Architecture:** Private debt ledger with customer locks/version and sale allocations;
existing sale/return/cancel business commands stay atomic with debt effects.
**Tech Stack:** React, TypeScript, Supabase PostgreSQL; no new dependency.
**Spec:** docs/superpowers/specs/2026-10-06-customer-debt-design.md

## Global Constraints

- No Cloud fixture rows, Docker or Supabase local; isolated PostgreSQL via Unix socket.
- Money canonical numeric(20,2), no JS Number arithmetic for amounts.
- RLS force/private tables, permission checks, empty privileged search_path.
- Preserve pre-existing user edits in three unrelated plan files.

## Review Focus

- Same-key requests with changed amounts/customer must not change existing ledger.
- Concurrent collection/return/adjustment must preserve nonnegative, reconciled balances.
- Manual write-off must not be reported as money received or refunded.
- Lost response/reload must block new financial command until prior key resolved.
- Anonymous/own-sale-only callers must not see another customer's aggregate debt.
